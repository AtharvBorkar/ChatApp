01 Executive Summary

ChatApp is a full-stack, distributed chat platform designed for reliable messaging, instant media exchange, and secure passwordless authentication. The backend is partitioned into independent microservices communicating synchronously via REST and asynchronously through RabbitMQ message queues.

This architecture decouples CPU- and I/O-intensive operations (such as email delivery and media uploads) from core API request paths, providing high availability, low request latency, and granular scalability.

03 Microservices Deep Dive

User Service backend/user

Authentication & Identity Provider

  • Passwordless email login via 6-digit OTP codes.
  • Redis rate limiting (60s cooldown per email) to stop spam.
  • Automatic user provisioning upon first successful OTP verification.
  • Issues HMAC-SHA256 JWT tokens with 15-day expiration.
  • Publishes background events to RabbitMQ.

Chat Service backend/chat

Conversation & Messaging Core

  • 1-on-1 thread creation and duplicate-prevention index.
  • Unseen message count aggregation per conversation.
  • Cloudinary storage integration via Multer for photos/attachments.
  • Inter-service user hydration from User Service via Axios.
  • Automatic read receipts (marking seen/seenAt timestamp).

Mail Service backend/mail

Async Notification Worker

  • Event-driven worker consuming from RabbitMQ queue send-otp.
  • Nodemailer SMTP integration for guaranteed delivery.
  • Protects the core API from email latency (1-3 sec saved per login).
  • Explicit message acknowledgments (channel.ack) prevent message loss.

04 API Specification & Routes

1. User Service Routes (/api/v1)

Method Endpoint Auth Required Description & Actions
POST /login No Checks rate limit in Redis, generates 6-digit OTP, stores in Redis (5 min TTL), publishes to RabbitMQ send-otp.
POST /verify No Validates submitted OTP with Redis. Creates user in Mongo if first time. Issues and returns JWT token + user object.
GET /me Bearer JWT Retrieves the authenticated user's profile details.
GET /user/all Bearer JWT Lists all registered users in the platform for starting new conversations.
GET /user/:id No Lookup user profile by ID. Used internally by the Chat Service to hydrate participant metadata.
POST /update/user Bearer JWT Updates the authenticated user's display name and re-issues a fresh JWT token.

2. Chat Service Routes (/api/v1)

Method Endpoint Auth Required Description & Actions
POST /chat/new Bearer JWT Finds existing chat between the 2 users or instantiates a new Chat document.
GET /chat/all Bearer JWT Fetches all user chats sorted by last activity, calculates unread counts, and hydates the other user's profile via REST.
POST /message Bearer JWT Uploads attachment to Cloudinary (if present), stores message in MongoDB, and updates conversation's latestMessage.
GET /message/:chatId Bearer JWT Fetches message history for a conversation and marks unread incoming messages as seen: true with timestamp.

05 Key Lifecycle Sequences

Authentication & OTP Sequence

1
User enters email in Frontend & submits to POST /api/v1/login.
2
User Service checks Redis otp:ratelimit:<email> (blocks if active).
3
6-digit OTP stored in Redis (TTL: 300s); Event pushed to RabbitMQ.
4
Mail Worker receives event from RabbitMQ & sends email via Gmail SMTP.
5
User inputs code to POST /api/v1/verify; verified against Redis & JWT issued.

Chat & Messaging Sequence

1
Sender triggers POST /api/v1/message with text and/or image file.
2
Multer uploads file to Cloudinary & returns CDN URL and publicId.
3
New Messages doc created in MongoDB; Chat.latestMessage updated.
4
Recipient opens conversation via GET /api/v1/message/:chatId.
5
Chat Service executes batch update setting seen: true and seenAt: now().

06 Database Schema Models

User Model

Collection: users

  • name: String (required)
  • email: String (unique, required)
  • createdAt: Date
  • updatedAt: Date

Chat Model

Collection: chats

  • users: [String] (participants)
  • latestMessage: { text, sender }
  • createdAt: Date
  • updatedAt: Date

Message Model

Collection: messages

  • chatId: ObjectId (Ref Chat)
  • sender: String
  • text: String
  • image: { url, publicId }
  • seen: Boolean, seenAt: Date

07 Roadmap & Production Recommendations

1. Real-time WebSocket Integration

Complete the Socket.io hooks in Chat Service for instantaneous push notifications, live typing indicators, and real-time read receipt updates without polling.

2. API Gateway Configuration

Implement a unified reverse proxy (e.g. Nginx, Kong, or Next.js rewrites) to expose services under a single domain (e.g. /api/user and /api/chat), eliminating CORS complexity.

3. Frontend Interface Buildout

Implement responsive chat UI components in frontend/src/app, integrating Zustand or React Query for state management and caching.
